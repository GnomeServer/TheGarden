## What the candidate branch actually provides

`origin/VaultGuard` contains a Keybroker client: the worker posts `run_id` and `operation` to `POST /v1/sessions`, uses the returned session key/model endpoint in process memory, and attempts `DELETE /v1/sessions/{session_id}` during cleanup. This is the required lease concept, but the candidate is **not a compatible drop-in for the current worker or smoke-test contract**:

- Relative to `origin/factory-testing`, the branch changes 57 files (`+793/-9184` in the local Git diff). It replaces the current OMP-container mission runner with `mission.py` model calls in the worker process, deletes the OMP image entrypoint and the current artifact/credential test suites, and removes Manager artifact/incident functionality. TC-01/03 require the specified container lifecycle; TC-04 needs the compatible failure/output path; TC-06 explicitly expects bounded OMP-container cleanup. TC-05 expects live cancellation, which is also absent. The branch does not provide that same execution path.
- Its Manager documentation says cancellation publishes `agent.runs.cancelled` but that nothing consumes the event; the candidate worker has no cancellation-event consumer. TC-05 cannot pass on this candidate.
- The candidate worker no longer enforces an HTTPS scheme for `KEYBROKER_URL`, no longer calls `GET /v1/worker/identity` before minting, and no longer uses the former `MODEL_CA_FILE` setting for Keybroker requests. Its README relies on installing the private Caddy root into the system trust store. The code also has a `MODEL_TLS_INSECURE` bypass; it must remain disabled. These are blockers until an owner-approved compatible commit restores the required TLS and identity protections or the owner supplies a reviewed equivalent.
- Candidate defaults are production-facing: `KEYBROKER_URL` and the broker's model URL point to the lab gateway; broker defaults are model `luna`, `$25` per-session budget, 3,600-second TTL, and a 60-second expiry-reaper interval. They are not test configuration. A dedicated test broker/gateway must set explicit test policy and endpoints.

The candidate's broker contract is source-IP based: Caddy injects `X-Darkfactory-Client-IP` and a server-side `X-Darkfactory-Proxy-Token`; Keybroker maps that IP to a worker ID. The worker does not send a per-worker bearer credential or trusted `worker_id` in the session body. The proxy token and LiteLLM master/dashboard tokens belong only on their respective test services; never provide them to the worker. Verify the test identity through `GET /v1/worker/identity` before any mint.
